# 关节动画与 IK 学习指南

根据老师的第10讲《关节动画技术1》和第11讲《关节动画技术2》整理。先讲概念，再给出操作顺序，最后对应已经实现的 Unity 项目。课件中的例子、历史参考和算法说明是学习材料；本次实际实现范围以你的作业要求为准。

## 一、先理解这几个概念

### 1. 关节动画是什么

对有骨架、父子层级的物体做动画。例如人体手臂、机械臂、动物骨架。骨架负责确定动作，模型外皮负责显示外形。

第10讲第2—6页将它分成三个问题：怎样表示关节系统，怎样控制关节运动，怎样让模型表面跟着骨架运动。本次作业重点是前两个，不需要先制作人物模型或做蒙皮。

### 2. 骨骼、关节、根节点、末端影响器

- **骨骼 / 链杆（Link、Bone）**：相邻连接点之间的一段刚体。运动时保持长度不变。
- **关节（Joint）**：链杆相对上一级链杆旋转的位置。应把旋转轴放在连接处，而不是骨段正中间。
- **关节链**：骨段依次相连形成的链。本次是一条没有分支的开链。
- **根节点（Root）**：链条的起点。作业要求根部位置固定，不能随着拖动而平移。
- **末端影响器（End Effector）**：链条自由的一端，类似手的位置。
- **目标点（Target）**：希望末端到达的位置。目标点可以移动到不可达位置；这时末端与目标会分开。

参考：第10讲第8—12页。

**本项目怎样计数：**界面的 N 表示“转动关节数，包含根部”，会创建 N 段骨骼和一个额外的末端位置点 E。例如 N=5 时，转动关节是 J0—J4，E 是最后一段骨骼的端点；可见位置点共有6个。E 没有下一级骨段，因此不额外计算旋转角。这个约定已经写在界面，避免把骨段数、转动关节数和位置点数混在一起。

### 3. 父子层级与局部坐标

如果小臂是大臂的子物体，大臂旋转时，小臂及它的后代会一起跟着转。小臂自身还可以在大臂的基础上继续转动。

Unity 中用 Transform 的父子关系表达这件事。每一个关节是一个空对象，旋转它；骨段图形放到它的子物体里。下一关节的 localPosition 放在本段末端。

```text
J0（根关节，位置固定）
├─ Link_0（第一段骨骼的图形）
└─ J1（localPosition = 第一段长度）
   ├─ Link_1
   └─ J2
      └─ ……
         └─ E（末端位置）
```

**localPosition / localRotation** 是相对父对象的变换；**position / rotation** 是世界空间中的位置和朝向。父级的旋转已经包含在子物体的世界旋转里，不能把世界角度直接当局部角度再写一遍。

课件用齐次变换矩阵连乘表示：`顶点世界坐标 = 根变换 × 上一级变换 × 本级变换 × 顶点局部坐标`。Unity 的 Transform 层级会替你完成这串变换。

参考：第10讲第13—35页。

### 4. 状态向量与自由度

状态向量就是把可调整的关节参数放到一起，例如 `θ = [θ0, θ1, …, θN-1]`。本项目让所有关节在 XY 平面内绕 Z 轴转动，因此每个转动关节有1个旋转自由度。

“根部固定”在这里指根部**世界位置固定**，根关节仍然可以旋转。若根关节连旋转也锁死，可运动范围会进一步减小，那是另一种约束。

### 5. FK：已知角度，计算末端在哪

FK 是正向运动学。比如先指定肩膀转30°、肘部转45°，再算出手的位置。

二维两段链，根部在原点，长度为 L0、L1，两个局部旋转角为 θ0、θ1：

```text
x = L0 cos(θ0) + L1 cos(θ0 + θ1)
y = L0 sin(θ0) + L1 sin(θ0 + θ1)
```

第二段使用 `θ0+θ1`，因为它同时受到父关节与自身旋转的影响。

参考：第10讲第36—39页、第11讲第3—5页。

### 6. IK：已知末端想去哪，反求关节角度

IK 是逆向运动学。你把手拖到一个位置，程序反过来计算肩膀、肘部怎样转。

它不一定有唯一答案：同一个手的位置可能对应不同的手肘方向；目标太远时也可能没有解。因此程序通常从上一帧的姿态继续求解，并允许一个很小的误差。

本项目只约束末端**位置**，没有额外约束末端朝向、关节旋转上下限或自碰撞。多解时保留算法从当前姿态迭代出来的一个解。

### 7. 蒙皮与权重：理解即可，本题不需要实现

蒙皮是建立“骨骼怎样影响模型顶点”的关系。一个顶点可以受到多根骨骼共同影响，每根骨骼的影响程度叫权重。

例如连接处的一个顶点分别受两块骨骼0.5、0.5的影响，最终位置按两种骨骼变换的结果加权求和。通常权重归一化后总和为1。

课件的意思可以写成：`v' = Σ wi × Mi(动画姿态) × Mi(绑定姿态)^(-1) × v`。把绑定姿态中的顶点先变到骨骼空间，再按当前骨骼姿态变回世界空间。

参考：第10讲第40—50页。当前演示用刚性杆和球形关节点显示骨架，不涉及人物表面的变形。

## 二、第11讲的四类求解方法

### 1. 解析法

给出方程，直接解关节角。二维两段机械臂可以使用余弦定理，复杂的多段链则很难写出统一的解析公式。

本题允许选择关节数量，用迭代方法实现更合适。参考第11讲第7—14页。

### 2. CCD：一次只转一个关节

CCD（Cyclic Coordinate Descent，循环坐标下降）的思路最直观：从靠近末端的关节开始，逐个向根部处理。

设当前关节为 P，末端为 E，目标为 T：

```text
a = E - P
b = T - P
Δθ = atan2(ax*by - ay*bx, ax*bx + ay*by)
```

`Δθ` 是从“关节指向末端”转到“关节指向目标”的有符号夹角。把该关节后面的所有骨段绕 P 转动这个角度，再处理上一级关节。

本项目每次关节调整限制在±35°，默认每帧最多120轮。末端误差小于0.002单位时停止本帧计算。误差若仍未满足，下一帧继续从当前姿态迭代。

这里的±35°是**单次迭代步长**，不是关节的解剖学旋转限位。本项目没有给关节设置硬性角度范围。

优点是容易实现，也容易对应“计算每个关节角”的要求。缺点是某些姿态收敛较慢，未加其他约束时动作可能折叠，不保证得到最自然的姿势。

参考：第11讲第15—20页；实现见 `Assets/IKDemo/Scripts/IKSolvers.cs` 的 `CCD()`。

### 3. FABRIK：先调整位置，再恢复角度

FABRIK（Forward And Backward Reaching Inverse Kinematics）用两次位置调整保持骨长：

1. 把末端暂时放到目标，从末端向根部逐段回推，每段保持原长度。此时根部可能离开原位。
2. 把根部放回固定位置，从根部向末端逐段前推，同样保持每段长度。
3. 反复执行，直到误差够小或达到迭代上限。

**注意课件中的叫法：**第21页的文字与第22页伪代码对“前向 / 后向”的命名顺序不一致。学习和写代码时，直接记住“末端→根部”和“根部→末端”这两个实际方向，就不会混淆。

FABRIK 得到一组关节位置后，还要把每段的方向换算成角度。本项目没有只画一条折线，而是进一步把计算出的角度写回真实的 Transform 父子层级。

参考：第11讲第21—23页；实现见 `IKSolvers.cs` 的 `FABRIK()`。

### 4. 雅克比方法：角度小变化与末端小变化的关系

核心关系是：`Δp ≈ J(θ) Δθ`。

- `Δp`：希望末端发生的一小段位移。
- `Δθ`：关节角度的一小段变化。
- `J`：雅克比矩阵，描述当前姿态下各关节变化如何影响末端。

二维位置加 N 个关节时，J 是2×N矩阵；若三维只管位置，则是3×N。矩阵随着姿态变化，迭代时要重新计算。关节完全伸直附近，某些移动方向难以通过很小的关节变化实现，可能出现奇异或病态问题。

第11讲第55页的阻尼最小二乘可以理解为：用更保守的角度变化，减少接近奇异姿态时的剧烈波动。此次作业不需要把四种算法全都实现；项目提供 CCD 和 FABRIK 供切换比较。

**课件第48—51页有两处需要纠正：**

- Moore–Penrose 伪逆对于任意有限实矩阵都存在，不能把“矩阵奇异”理解为“伪逆不存在”。真正的问题是某些目标速度不在雅克比的可达子空间中，不能精确实现；接近奇异时还可能出现数值敏感。
- `(JᵀJ)^(-1)Jᵀ` 要求 J **列满秩**；若 J **行满秩**，对应的是 `Jᵀ(JJᵀ)^(-1)`。课件第49页把前一种公式的条件写成了行满秩，学习时应修正。

这些是数学条件说明，不影响本次 CCD / FABRIK 演示。没有把课件中的简化表述直接搬进代码。

## 三、这次作业的大致操作顺序

如果你需要自己从零复现，可以按下面做；已经交付的 IK 项目已完成这些步骤。

1. **准备场景。** 创建3D场景，设置正交相机朝向 XY 平面。先限制关节绕 Z 轴旋转，避免初学时把空间旋转与 IK 迭代混在一起。
2. **确定数量定义。** 输入 N 个转动关节，建立 N 段骨骼以及额外末端点 E。
3. **建立父子结构。** 每个关节用空对象做 Pivot；骨段图形放在它的子物体里；下一关节的局部位置放在前一段末端。骨段图形居中，但 Pivot 留在连接点。
4. **记录约束。** 保存根部的世界位置、每一段的长度。运行中固定根部位置，只改变旋转。
5. **读取鼠标目标。** 点击末端或红色目标后，把屏幕射线与 z=0平面求交，得到目标世界坐标。不要直接把鼠标的像素坐标当世界坐标。
6. **判断可达。** 对这条没有关节限位、各段等长且至少两段的平面链，目标到根部距离若超过总长度，就让链伸直朝向目标。
7. **执行 CCD 或 FABRIK。** 满足误差容差或迭代上限就结束本帧。目标可达但还没收敛时，下一帧继续计算。
8. **恢复角度。** 对每段算世界朝向 `αi = atan2(dy,dx)`；根关节局部角等于 `α0`，其余局部角等于相邻世界朝向之差，并归一化到有符号角范围。
9. **写回层级。** 将局部角写到各关节的 `localRotation`。下一关节的 `localPosition` 仍保持原来的骨长，因此不会靠拉长骨骼来追目标。
10. **加交互与验证。** 关节数量、骨段长度、创建按钮、求解方法切换、暂停、单步、角度列表，以及根部偏移和骨长误差显示。

公式里的 `atan2` 返回弧度；写入 Unity 的 Euler 角前要乘 `Rad2Deg` 转成度。

## 四、直接使用已经做好的项目

项目目录：`D:\unity\项目\IK`

场景：`Assets/IKDemo/Scenes/IK_Demo.unity`

1. Unity 中打开该场景，点击上方 ▶ Play，切到 Game 页签。
2. 左侧选择2—20个转动关节，可同时调整每段长度，再点“创建 / 重建关节链”。
3. 按住鼠标左键拖动浅色末端 E，也可以拖红色目标十字。
4. 看根部 J0 是否仍在原位、骨段长度是否不变。拖出可达圆后，末端不会假装追上目标，界面会显示不可达及实际误差。
5. 切换 CCD / FABRIK，比较运动方式。点击“暂停求解”后，目标仍能拖动；按“单轮迭代”可观察一轮如何使末端接近目标。
6. R 重置姿态；Space 暂停 / 继续。关节多时，左侧角度区域可用鼠标滚轮查看。

默认参数：5个转动关节，每段1单位，CCD，每帧最多120轮，容差0.002单位。

可达圆表示最大距离，总长为 `N × 每段长度`。一般不等长骨段还可能存在内部不可达区域，但本项目使用等长链且至少两段，因此没有这个问题。圆内出现“正在迭代”表示目标在几何上可达，不代表本帧已经精确收敛。

## 五、代码对应关系

- `IKSolvers.cs`：CCD 与 FABRIK 核心求解、目标太远时的伸直处理，以及完全共线时的小幅弯曲初始化。每次位置调整都保持根部和骨长约束。
- `IKChainDemo.cs`：关节层级生成、鼠标拖拽、角度恢复、界面和误差显示。
- `Editor/IKProjectSetup.cs`：创建并保存演示场景、生成材质、数学检查、Play 模式检查，以及可选 Windows 构建。
- `IKRuntimeVerification.cs`：只在手动请求验证时运行，不影响平时使用；检查实际 Transform 的根部位置、骨长和末端误差。

Unity 顶栏的 `IK` 菜单提供打开场景、数学检查、Play Mode 检查和 Windows 构建。自动创建只在演示场景不存在时触发；已有场景不会被自动覆盖。

## 六、演示或交作业时可以这样解释

“我先按用户选择的数量生成转动关节，并用 Transform 父子层级把骨段连接起来。根部的世界位置固定，每一段长度固定。用户拖动末端时，我把鼠标投影到 XY 平面得到目标位置，再用 CCD 从末端向根部逐关节调整，让末端逐渐靠近目标。也可以切换 FABRIK，先反复调整关节位置，再把每段方向换成局部旋转角。目标超过总链长时，我让关节链伸直到最近的位置，并显示实际误差。”

如果老师问“为什么根关节的角度会变化”，回答：固定的是根部位置，绕固定根部旋转不会让根部平移。

如果老师问“为什么某个角度超过了90度”，回答：当前演示没有给关节加人体角度限位，±35度限制的是 CCD 每次调整的步长，不能当作关节限位。

如果老师问“这是不是物理关节”，回答：这是运动学关节链，靠几何求解和 Transform 旋转工作，不是用 Rigidbody / HingeJoint 受力模拟出来的。
